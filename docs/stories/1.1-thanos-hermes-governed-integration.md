# Story 1.1 — Integração governada THÁNOS → Hermes

## Status

Implementação, validação no sandbox MySQL e prova controlada contra o Hermes real concluídas; M19 pronta para auditoria externa, sem rollout produtivo.

## Objetivo

Permitir que uma mensagem elegível ao piloto THÁNOS use o provider Hermes configurado para o tenant depois da execução local das tools READ, preservando fallback determinístico, isolamento, `requestId` e auditoria sanitizada.

## Acceptance Criteria

- [x] O mesmo request registra `route=thanos`, `provider=hermes`, `fallback=false`, `mode=multi_read`, `toolCount=3` e as três tools autorizadas.
- [x] `PastoralThanosFacade` reutiliza a instância governada de `AgentGateway`/`HermesClient`; não cria um segundo cliente Hermes.
- [x] A configuração `provider=hermes` é resolvida por organização no caminho THÁNOS.
- [x] Falhas `timeout`, `network_error`, `response_error` e `circuit_open` retornam fallback determinístico sem repetir tools, mensagem de usuário ou resposta.
- [x] Kill switch e audiências de organização/usuário continuam roteando ao legado antes do THÁNOS.
- [x] Tenant e `requestId` permanecem iguais na rota, nas tools, no provider e na auditoria.
- [x] Status, auditoria e resposta não expõem chave, URL, token, allowlist, prompt privado ou evidência pastoral bruta.
- [x] Nenhuma operação WRITE/SENSITIVE, n8n, voz ou canal adicional é habilitada.
- [x] Testes focalizados, suíte completa, `pnpm check` e `pnpm build` passam.
